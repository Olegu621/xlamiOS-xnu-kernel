Will it work on my phone?

One phone runs it today: the POCO F6 (peridot, SM8635 / Snapdragon 8s Gen 3). Every other phone needs a port, and a port here means rewriting the hardware-facing code, not changing a setting. This page lists what a phone has to have, and then groups the realistic candidates by chip family.

The basics your phone needs

  • An unlockable bootloader that supports fastboot boot (booting an image from the PC without flashing it). Xiaomi and Poco bootloaders can do this. Samsung phones use Odin instead of fastboot, and Huawei bootloaders can't be unlocked anymore.
  • A 64-bit ARM chip. Every phone from the last eight or so years has one.
  • UFS storage. xlamiOS has its own UFS host driver; on this phone the controller is at 0x1d84000. Phones with eMMC storage (common in budget models) need a new storage driver first.
  • Enough RAM. The kernel uses the upper DDR bank: on this phone the high-memory window is a 3 GiB contiguous block at 0x08c0000000, plus a private DMA arena for the display and the SPI engine. The kernel can't use all of the phone's memory — the low bank is broken up by carve-outs — which is why the port uses the high window.
  • A screen the bootloader leaves on. xlamiOS draws into the image buffer the bootloader uses for its logo, on this phone the splash region at 0xe3940000. Almost all Qualcomm phones do this.

Chip families

ChipChanceWhat a port involves
Snapdragon 8s Gen 3 (SM8635)
POCO F6, codename peridot		 Best This is the port that exists. The kernel drives the v7 SPMI arbiter for the keys, the serial engine SE4 at 0xa90000 for the touch panel, the qcom,cliffs-gcc clock controller and the internal UFS. The panel is a Goodix BerlinD (9916R) whose registers are read over bit-banged SPI, and the keys come from the PMIC over SPMI.
Snapdragon 8 Gen 1 and newer
every 8-series chip from the 8 Gen 1 on		 Good Same building blocks as the SM8635: the same interrupt controller type, the same kind of power controller (RPMh) and the same serial engines. The details differ per family — the clock controller has a different compatible string, the SPMI arbiter may be an older revision, and the serial engine's DMA path needs its own SMMU route. So a port means new board data (memory map, storage, screen, touch, buttons) and a new SPI transport, not a new kernel.
Older Snapdragon
SM7150 and the 7xx generation		 Hard This project started on the Redmi Note 10 Pro (SM7150, sweet) and that port was paused in October 2026. Its code path is deliberately gated off on SM8635: the SM7150 key, touch and USB probes are refused on this SoC, because they read registers that mean something else here. Bringing that board back is a port in its own right.
Snapdragon with eMMC
many 4xx and some 6xx phones		 Hard Everything in the row above that matches your chip, plus a new eMMC (SDHCI) storage driver, since the iOS root has to live somewhere and all of the storage work here is a UFS host driver.
Google Tensor (Pixel 6 and later) Separate port The bootloader is friendly, but the chip is Google's own design, built on Samsung's platform up to Tensor G4, and shares almost nothing with Snapdragon. The shim and every driver would be new. Ports for these are separate projects.
MediaTek (Helio, Dimensity) Probably not Different hardware from the ground up, bootloaders that are often hard to unlock, and vendor kernel sources that are harder to learn from. It's not impossible, but it would be a new project rather than a port.
Exynos, Unisoc, Kirin Probably not Same story as MediaTek. On top of that, Samsung phones have no fastboot boot and Huawei bootloaders can't be unlocked.

Quick answers

POCO F6?

Yes. SM8635, Snapdragon 8s Gen 3, 12 GB of RAM, UFS 4.0 and a 1220 x 2712 panel. Everything in the table above the SM7150 row is about making that work.

Another phone with the same chip?

It would be a real port, not a configuration change. The platform is peridot, but the board data is not shared: the panel, the touch controller, the key wiring and the memory map all come from your own phone's device tree. The kernel's peridot path is gated to the SM8635, and the old SM7150 probes are refused there on purpose.

My phone is MediaTek (Redmi Note 9, many Redmi and Realme models).

Probably not. Look up the exact chip first: some phones sold under the same name come in both a MediaTek and a Snapdragon version.

Can I run iPadOS on my Android tablet?

Not with this project. iPadOS comes from a different firmware and expects iPad hardware. The same approach could work in theory, but nobody has done it.

Can it run iOS 17, 18 or newer?

Not on this path. Every iPhone that runs iOS 17 or newer is built for pointer authentication (arm64e). The kernel here is built in plain arm64, and the userland is the iPhone X's, so this path stops at iOS 16. (Why an iPhone X?)

How do I find out which chip I have?

Search your model on GSMArena and look at the "Chipset" line, or install an app like CPU-Z. The storage type (UFS or eMMC) is listed there too.
