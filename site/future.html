Future plans

No dates and no promises. This is a hobby project, and every new piece of hardware means writing a driver from scratch. Here's what's being looked at.

The touch path

The panel is a Goodix BerlinD (9916R) on the serial engine SE4. Two transports have been tried. The engine's FIFO mode cannot receive on this board, and the GPI DMA path moves the bytes correctly but never gets its completion event, so the transfer times out.

The simple path is the one being taken now: the four panel pins are muxed back to plain GPIOs and the Goodix protocol is bit-banged by hand, which needs no DMA engine and no SMMU at all. The panel's own rails are voted through RPMh and its reset is sequenced on its GPIO.

What is still missing is the last step: turning those register reads into HID digitizer events, and proving them with a finger. The path exists today, but it has not been exercised by a hand.

GPU acceleration (maybe)

Right now the CPU draws every frame. iOS draws through Apple's Metal interface, so a GPU driver would have to accept Metal work and turn it into commands for the phone's GPU. Nobody has done that for this GPU under iOS, and Apple doesn't document how its GPU drivers talk to the system.

It might be possible. Open-source drivers for these GPUs exist on Linux, so the hardware side is fairly well understood. Still, this is the hardest item on the list by far. If it ever happens, it will take a long time.

Wi-Fi, Bluetooth and the other radios

The phone has a Qualcomm Wi-Fi and Bluetooth chip, and it's a lot more involved than the keys were. Before the chip does anything, its firmware has to be loaded and it has to be brought up through Qualcomm's remote processor interface. After that, iOS needs to see it as a network interface its own Wi-Fi stack can drive, and Bluetooth needs something that looks like Apple's Bluetooth controller.

What exists today is identity, not drivers: the device tree carries synthetic wifi0 and bluetooth0 MAC addresses, because MobileGestalt blocks on a missing network-driver identity and SpringBoard never got past that wait. That unblocked the GUI. It did not bring up a radio.

The USB gadget is not ported to this board either: the USB core here is DWC_usb31 (GSNPSID 0x33313130), not the one the older board used, so streaming the log live over USB is still work to do. Audio, the camera and the sensors are in the same state: nothing yet.

More phones

That part is up to you. Ports to other Snapdragon phones are the fastest way for this to grow. Start with the porting guide and share your progress on r/hackios.

Follow along

The commit history on GitHub is the most up-to-date status. Every kernel change is a numbered patch, and NOTES.md logs each boot attempt, including the ones that failed.
